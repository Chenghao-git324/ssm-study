> 用法：先自己答，答不出再看答案。标 ★ 的是高频。

## 一、Spring 内核

### 1. ★ 什么是 IoC 和 DI？两者什么关系？

- **IoC（控制反转）**：对象的创建权从程序员 `new` 反转给容器管理。
- **DI（依赖注入）**：容器在创建对象时，把它依赖的对象注入进去。
- **关系**：IoC 是思想，DI 是实现手段。Spring 用 DI 实现 IoC。

### 2. ★ Bean 的生命周期？

```
实例化（构造方法）
  → 属性注入（setter / @Autowired）
  → BeanNameAware / BeanFactoryAware 等回调
  → BeanPostProcessor.postProcessBeforeInitialization
  → @PostConstruct / InitializingBean.afterPropertiesSet / init-method
  → BeanPostProcessor.postProcessAfterInitialization  ← AOP 代理在这里生成
  → 使用
  → @PreDestroy / DisposableBean.destroy / destroy-method
```

单例 Bean 在**容器启动时**创建；`prototype` 每次 `getBean` 新建，容器关闭不销毁。

### 3. 单例 Bean 线程安全吗？

**不安全**。Spring 不保证单例 Bean 的线程安全，取决于 Bean 内部是否有可变状态。无状态（只有方法、没有可写字段）的 Service 是安全的；有成员变量且被并发修改就有问题。

### 4. ★ 构造器注入 vs 字段注入？

| | 构造器注入 | 字段注入（@Autowired） |
|---|---|---|
| 不可变 | 可 `final` | 不行 |
| 循环依赖 | 启动就报错（好事） | 可能隐藏问题 |
| 测试 | 方便 new | 需要反射 |
| 官方推荐 | ✅ | ❌ |

Spring 官方推荐构造器注入；苍穹外卖的 `@RequiredArgsConstructor` + `final` 就是这种写法。

### 5. BeanFactory vs ApplicationContext？

- `ApplicationContext` 是 `BeanFactory` 的**子接口**。
- `BeanFactory`：懒加载，`getBean` 时才创建。
- `ApplicationContext`：启动时预加载所有单例，多了事件、国际化、资源加载等能力。日常用后者。

### 6. @Bean vs @Component？

- `@Component`：**自己的类**，Spring 扫描后创建（类上加）。
- `@Bean`：**第三方类**（无法改源码），在配置类的方法里手动创建并注册。
- 规律：能加 `@Component` 就加；不能改源码的用 `@Bean`。

### 7. @Autowired vs @Resource？

- `@Autowired`：Spring 提供，**按类型**注入；多个同类型时配合 `@Qualifier` 按名字。
- `@Resource`：JDK（JSR-250）提供，**默认按名字**，找不到再按类型。

### 8. AOP 的五个概念？

| 概念 | 说明 |
|---|---|
| 连接点 JoinPoint | 可以被增强的点（方法调用） |
| 切入点 Pointcut | 实际被增强的点（execution 表达式） |
| 通知 Advice | 增强的逻辑（@Before / @After / @Around...） |
| 切面 Aspect | 切入点 + 通知 = 一个类 |
| 目标对象 Target | 被代理的原始对象 |

### 9. ★ 五种通知的执行顺序？

```
@Around 前半段
  @Before
    目标方法
  @AfterReturning / @AfterThrowing
  @After
@Around 后半段
```

`@Around` 能拿到 `ProceedingJoinPoint`，可控制是否 `proceed()`、修改参数和返回值；其它通知只能"旁观"（`@Before` 可改参数数组）。

### 10. ★ AOP 底层是 JDK 代理还是 CGLIB？

- 目标类**有接口** → 默认 JDK 动态代理（基于接口）。
- **无接口** → CGLIB（生成子类）。
- Spring Boot 2.x 起默认强制使用 CGLIB（`spring.aop.proxy-target-class=true`）。

### 11. ★ AOP / 事务为什么会失效？

1. **同类内部调用**（`this.method()` 不走代理）
2. 方法不是 `public`
3. 类没有被 Spring 管理（自己 new 的）
4. 异常被自己 try-catch 吃掉
5. 两个容器扫描重叠，拿到的是未被代理的副本（关 10 的坑）

### 12. ★ @Transactional 的原理？

AOP 代理：方法调用前后由 `TransactionInterceptor` 开启/提交/回滚事务。

### 13. ★ 事务失效的场景（至少说 4 个）

见第 11 题；再加：
- 抛的是**受检异常**且没写 `rollbackFor`（默认只回滚 RuntimeException）
- 数据库引擎不支持事务（MyISAM）
- 多线程调用（事务绑定在 ThreadLocal 上）

### 14. ★ 传播行为 REQUIRED vs REQUIRES_NEW？

- `REQUIRED`（默认）：有事务就加入，没有就新建。
- `REQUIRES_NEW`：**挂起**当前事务，自己新开一个；自己提交/回滚不影响外层。
- 场景：转账日志用 `REQUIRES_NEW`，业务回滚了日志也要留下。

### 15. rollbackFor 为什么必须写？

`@Transactional` 默认只对 `RuntimeException` 和 `Error` 回滚，受检异常（如 `IOException`）**不回滚**。写 `rollbackFor = Exception.class` 才覆盖所有异常。

## 二、SpringMVC

### 16. ★ SpringMVC 处理一个请求的流程？

```
浏览器请求
 → Tomcat
 → DispatcherServlet（唯一入口，映射 /）
 → HandlerMapping 找到 Handler（Controller 方法）
 → HandlerAdapter 执行（解析参数、调用方法）
 → 返回 Result / ModelAndView
 → @ResponseBody 则 HttpMessageConverter 写响应体
   否则 ViewResolver 解析视图
 → 响应浏览器
```

口诀：**Mapping 找人，Adapter 干活。**

### 17. ★ Root 容器和 SpringMVC 容器的分工？

| 容器 | 配置 | 内容 |
|---|---|---|
| Root（父） | `getRootConfigClasses()` | Service、Mapper、数据源、事务、AOP |
| MVC（子） | `getServletConfigClasses()` | Controller、拦截器、异常处理 |

- 子能看父，父不能看子。
- 两个容器都扫同一个包 → 同一个类被创建两份，Controller 拿到 MVC 容器里的裸对象，**事务静默失效**。

### 18. ★ @RequestParam / @PathVariable / @RequestBody 区别？

| 注解 | 数据来源 | 场景 |
|---|---|---|
| `@RequestParam` | URL 参数 / 表单 | `?id=1` |
| `@PathVariable` | 路径占位符 | `/books/1` |
| `@RequestBody` | 请求体（JSON） | POST/PUT 提交对象 |

### 19. ★ 前端传 JSON，后端忘写 @RequestBody 会怎样？

**HTTP 200，参数全 null，不报错**。Spring 把对象当 ModelAttribute，去 URL 参数里找属性名，找不到就 null。这是最隐蔽的坑。

### 20. 拦截器的三个方法、执行顺序？

```
preHandle（正序）→ Controller → postHandle（倒序）→ afterCompletion（倒序）
```

`preHandle` 返回 `false`：后续 `preHandle` 和所有 `postHandle` 不执行，`afterCompletion` 只对已通过 `preHandle` 的拦截器执行。

### 21. ★ 拦截器 vs 过滤器？

| | Filter | Interceptor |
|---|---|---|
| 归属 | Servlet 规范 | SpringMVC |
| 位置 | DispatcherServlet 之前 | DispatcherServlet 之后 |
| 能拿到 | request/response | 还能拿到 **handler** |
| 用途 | 编码、跨域、压缩 | 登录、权限、接口耗时 |

### 22. 全局异常处理怎么做？

`@RestControllerAdvice` + `@ExceptionHandler`：
- 业务异常 → 返回统一 `Result`，消息给用户看
- 系统异常 → 打堆栈，返回「系统繁忙」
- Spring 按**最精确匹配**选择 handler

## 三、Maven

### 23. ★ 聚合和继承的区别？

- **聚合** `<modules>`：一次构建多个模块（管**构建**）。
- **继承** `<parent>`：子模块继承父的版本、插件、properties（管**配置**）。
- 父 pom 通常两件事一起做。

### 24. ★ 依赖传递 / optional / exclusions？

- **传递**：A→B→C，A 自动拿到 C。
- **optional**：我依赖你，但不往下传；下游要用得自己声明。
- **exclusions**：传下来的某个 jar 我不要。
- 排查：`mvn dependency:tree`。

### 25. 依赖冲突怎么解决？

1. `dependency:tree` 找出来源
2. `exclusions` 排除
3. `dependencyManagement` 锁版本
4. 就近原则：Maven 默认取路径最短的版本

### 26. profile 多环境怎么配？

```xml
<profiles>
  <profile>
    <id>dev</id>
    <activation><activeByDefault>true</activeByDefault></activation>
    <properties><jdbc.db>ssm_db</jdbc.db></properties>
  </profile>
</profiles>
```
配合 `<resources><filtering>true</filtering></resources>`，打包时替换 `${jdbc.db}`。

### 27. -DskipTests vs -Dmaven.test.skip=true？

- `skipTests`：跳过**执行**，测试代码照样编译。
- `maven.test.skip`：连**编译**都跳过。
- CI 用前者（保证测试代码能编译），本地图快用后者。

### 28. 私服的三级结构？snapshot vs release？

```
本地仓库 → 公司私服（proxy/hosted/group）→ 中央仓库
```

| | SNAPSHOT | RELEASE |
|---|---|---|
| 覆盖 | 可以 | 不可以 |
| 检查更新 | 每次构建检查 | 本地有就用 |

## 四、SpringBoot

### 29. ★ starter 是什么？

**依赖的组合包 + 自动配置的组合**。例如 `spring-boot-starter-web` = spring-webmvc + 内嵌 Tomcat + Jackson + 自动配置。

### 30. ★ 自动配置原理？

```
@SpringBootApplication
 → @EnableAutoConfiguration
 → @Import(AutoConfigurationImportSelector)
 → 读 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
 → 得到 150+ 自动配置类
 → 每个类按 @ConditionalOnClass / @ConditionalOnMissingBean 判断是否生效
```

### 31. ★ 配置优先级（从高到低）？

```
命令行参数 > 环境变量 > jar 外 application-{profile} > jar 内 application-{profile}
> jar 外 application > jar 内 application > @PropertySource > 代码默认值
```
同位置下 `properties` 优先于 `yml`。

### 32. @ConfigurationProperties vs @Value？

| | @ConfigurationProperties | @Value |
|---|---|---|
| 一次绑定 | 整组 + 嵌套对象 | 单个值 |
| 松散绑定 | 支持 | 不支持 |
| 找不到时 | 静默 null | 启动报错 |

### 33. Spring Boot 和 SSM 是什么关系？

Boot = Spring + SpringMVC + 约定 + 自动配置 + 内嵌服务器。SSM 的全部知识仍然适用，Boot 只是把装配自动化了。

## 五、MyBatis / MyBatis-Plus

### 34. ★ Mapper 接口没有实现类为什么能用？

MyBatis 用 **JDK 动态代理**生成实现类：`SqlSession.getMapper()` 返回代理对象，方法调用被转发到 `MapperMethod`，根据 `namespace + 方法名` 找到 SQL 并执行。

### 35. ★ #{} 和 ${} 的区别？

- `#{}`：预编译占位符 `?`，**防 SQL 注入**。
- `${}`：字符串拼接，原样拼进 SQL，**有注入风险**。
- 只在动态表名、列名这种无法用 `?` 的地方用 `${}`，且必须白名单校验。

### 36. ★ MyBatis-Plus 和 MyBatis 什么关系？

MP 是 MyBatis 的**增强**，不是替代。单表 CRUD 由 MP 生成 SQL，复杂 SQL 仍写 XML，两者共存于同一个 Mapper 接口。

### 37. ★ BaseMapper 常用方法？

```
insert / deleteById / deleteByIds / updateById
selectById / selectList / selectOne / selectCount / selectPage / selectBatchIds
```

### 38. ★ QueryWrapper vs LambdaQueryWrapper？

- 字符串列名 → 写错**运行时**才报，重构不提示。
- Lambda 方法引用 → 写错**编译期**报错，字段改名自动提示。**推荐 Lambda**。

### 39. 分页插件的坑？

不注册 `PaginationInnerInterceptor` 时，`selectPage` **不报错**，返回全部数据。

### 40. ★ 逻辑删除怎么实现？

`@TableLogic` + 实体的 `deleted` 字段：
- 删除 → `UPDATE ... SET deleted=1 WHERE id=? AND deleted=0`
- 查询 → 自动追加 `WHERE deleted=0`
- 坑：手写 XML 要自己加 `and deleted=0`；唯一索引会冲突。

### 41. ★ 乐观锁 vs 悲观锁？

| | 乐观锁 | 悲观锁 |
|---|---|---|
| 实现 | `@Version` 版本号 | `select ... for update` |
| 冲突 | 失败重试 | 阻塞等待 |
| 适合 | 读多写少 | 写多、冲突频繁 |

### 42. ★ 雪花算法？为什么 Long 要转字符串给前端？

64 位：1 符号位 + 41 时间戳 + 10 机器 ID + 12 序列号 → 19 位、全局唯一、趋势递增。

JS `Number` 安全整数只到 2^53-1（16 位），19 位会丢精度，导致前端拿到的 id 和后端不一致。解决：`@JsonSerialize(using = ToStringSerializer.class)`。

## 六、综合

### 43. 为什么拆模块？

编译期强制分层（dao 看不到 controller）、依赖清晰、可复用、多人协作冲突小。

### 44. 从 SSM 迁到 Boot 删掉了什么？

`ServletContainersInitConfig`（内嵌 Tomcat）、`SpringMvcConfig`（自动配置）、`SpringConfig`（自动扫描）、`MyBatisConfig`（starter + yml）。

### 45. 讲一个你踩过的坑

示例（本项目的真实经历）：
- Tomcat 的 `DefaultServlet` 按平台编码转码静态文件，导致页面中文乱码 → `conf/web.xml` 加 `fileEncoding=UTF-8`
- MVC 容器扫到 Service，Controller 拿到无事务代理的副本 → 事务静默失效
- 前端发 JSON 少写 `@RequestBody` → 200 + 全 null
